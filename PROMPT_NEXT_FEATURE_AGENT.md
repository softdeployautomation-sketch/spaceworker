## 1. TASK_171 (FIRST AND ONLY) — zip-link history: all links, expiry, downloads

Owner: "i want the zip link generated for public use to show all links
generated by that user and also show how long more before it expires, and
also show how many downloads."

Surface: the agent installer's public ZIP link in the Add-a-device panel
(`components/device-list.tsx` public tab), NOT the hosting-panel short links.

Verified facts (reproduce, don't assume):

- One row per user: `VantraLink` (`prisma/schema.prisma:2162-2215`) is
  `@unique` on `userId`. Today's public mint (`mintInstallLink`,
  `lib/vantra-link.ts:485-565`) OVERWRITES `installTokenHash`,
  `installTokenExpiresAt` (+72h), `installUrl`, `installerUrl`,
  `installerNamesJson`, `installerKind` — so history is lost on every
  "New link". The panel only ever shows the CURRENT link
  (`components/device-list.tsx:866-958`).
- Open path: `GET /link/vantra/<token>`
  (`app/link/vantra/[token]/route.ts`) → `resolveInstallToken`
  (`lib/vantra-link.ts:627-669`) → 302 to the server-only `installerUrl`,
  or 410 when unknown/expired. There is NO download counter anywhere on
  this path (confirmed by grep — no `downloadCount` on VantraLink).
- Expiry exists per-row (`installTokenExpiresAt`, +72h at mint) but only the
  current row's is visible, as static text ("One-time link, valid 72 hours",
  `device-list.tsx:956-958`) — no live countdown.
- `VantraLinkView` (`lib/vantra-link.ts:59-87`) carries `installUrl` +
  `installTokenExpiresAt` but no history and no counts; `toView` is the
  only shape that leaves `lib/vantra-link` (server-only `installerUrl`
  rule — keep it).
